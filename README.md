# 青禾 · 电商运营助手

按《开发文档.md》从零实现的本地单品运营工作台。前端为 Vue 3 + TypeScript，后端为 FastAPI，数据库为 SQLAlchemy + SQLite，素材任务与竞品监控使用独立后台线程执行。默认无需模型密钥即可演示完整业务闭环。

## 立即启动

环境要求：Windows、Python 3.11+、Node.js 22.12+ 或 24。首次安装需要联网；后续演示无需外部模型服务。

在项目根目录双击 **启动项目.cmd**，或执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Demo
```

脚本按需安装依赖，构建前端，初始化数据库及演示数据，随后以前后端同源方式启动。重复初始化演示数据保留已有修改。

- 工作台：<http://127.0.0.1:8765>
- 交互接口文档：<http://127.0.0.1:8765/docs>
- 健康检查：<http://127.0.0.1:8765/api/health>
- 停止服务：在启动窗口按 `Ctrl+C`。

本机 Windows 将 7998–8097 划为保留端口范围，因此默认使用已验证可用的 **8765**。如端口不可用，启动时增加 `-Port 18080`。前端同源访问不需要额外改配置。

| 管理员 | `admin` | `Admin@123456` | 首次初始化数据库 |

这些密码仅适用于默认演示环境。设置了 `BOOTSTRAP_ADMIN_PASSWORD` 或已在设置页改过密码时，使用实际密码。初始化环境变量不会重置数据库内已有账户。

## 已实现的功能

- 登录、退出、角色权限、用户创建/修改/停用；改密码、改角色或停用会使已有令牌失效。
- 工作台、平台筛选、店铺列表/详情、商品列表/详情与商品图片地址。
- 商品平台映射、SKU 建档/编辑/启停、可用库存、库存锁定、库存调整流水与低库存提示。
- 竞品录入/编辑、公开页面静态元信息解析、监控启停、定时采集与失败快照。
- 可编辑的结构化商品诊断、至少三个方向的主图方案、至少三条视频脚本、方案状态管理。
- 持久化图片/视频任务、事件时间线、手动失败重试、取消、超时扫描；过期尝试或取消后的结果不会入库。
- 素材预览、人工审核、版本、评分、标签、场景与备注管理。
- 推广链接建议、UTM 参数、跳转与点击记录。
- 可编辑的投放建议、人工确认/驳回、关联已审核素材的实验计划、受控状态流转。
- 经营数据录入与批量导入、指标计算、周期复盘编辑，以及复盘返回下一轮诊断。
- 商品 / SKU 库存 / 经营数据 / 平台映射四类 CSV 模板与导入预览、行级错误、部分成功统计。
- 模型模式、任务参数、用户角色设置与演示数据初始化。

## 演示与真实服务的区别

| 能力 | 默认演示模式 | 可选真实服务 |
| --- | --- | --- |
| 诊断、方案、建议、复盘 | 基于商品与经营数据的确定性规则，标记 `demo_rules` | OpenAI 兼容的 JSON 文本接口，结果须通过结构校验 |
| 图片 | 带明确占位标识的 SVG 排版示意图 | `/images/generations`，要求返回 `b64_json` |
| 视频 | 可播放的 6 秒 MP4 动态分镜，明确标记非真实拍摄/AI 视频 | 自定义视频适配服务，协议见下文 |
| 平台账号 | 只保存授权占位与安全元数据 | 真实平台 OAuth 尚需针对具体平台开发接入 |
| 公开商品页面 | 提取静态标题、公开价格元信息、描述和主图 | 不执行浏览器登录，不绕过验证或访问限制 |
| 投放 | 生成建议、记录确认与实验状态 | 用户在平台手动执行；系统不提交广告、不扣费、不改平台预算 |

演示经营记录为合成数据；示意图中的商品造型不是商品实拍。真实模型接口已提供适配入口，但未使用真实密钥和付费服务联调。Docker 配置随项目提供，本次验证以 Windows 本地运行结果为准。

## 一条完整的演示链路

1. 管理员登录。在工作台点击“一键体验演示数据”，或使用启动脚本的 `-Demo` 参数。
2. 进入“商品池”，打开“青禾 · 轻量随行保温杯”。演示环境包含三家店铺、六件商品和完整单品示例。
3. 在“商品&竞品”维护档案，新增 SKU，执行一次库存调整，查看流水；补充竞品或解析一个允许公开访问的链接。
4. 在“诊断”生成并编辑商品诊断。主图/视频方案生成要求已有诊断。
5. 在“主图”或“视频”生成方案，编辑文案/分镜，标记选中后提交素材生成。
6. 到“任务”查看入队、运行和成功事件。任务失败可重试；待处理/运行中任务可取消。
7. 在“素材库”预览示意素材，填写评分、标签、备注并人工审核。演示发布前仍需替换真实商品素材。
8. 在“链接”创建追踪链接；通过此链接访问目标页后，刷新可看到点击次数。
9. 在“投放”生成建议，核对预算后人工确认，再创建实验计划；依次记录草稿、确认、运行、完成。
10. 在“复盘”录入或导入经营数据，选择覆盖这些数据的日期生成报告，编辑下一步动作，再点击“回到诊断”。下一轮演示诊断会引用最近复盘的动作建议。

## 目录与请求流程

```text
项目根目录
├─ backend/
│  ├─ app/
│  │  ├─ main.py              应用入口、初始化、后台执行器与前端托管
│  │  ├─ config.py            环境配置
│  │  ├─ models.py            数据表、外键和约束
│  │  ├─ schemas.py           请求与生成结果的结构校验
│  │  ├─ db.py                数据连接、事务与通用读写
│  │  ├─ security.py          密码哈希、令牌与角色权限
│  │  ├─ routers/             认证、商品、运营、工作区接口
│  │  └─ services/            库存、生成、任务、导入、公开解析与演示数据
│  ├─ scripts/               数据库初始化、SQL 导出、独立任务执行器
│  ├─ tests/                 使用临时数据库的业务与权限测试
│  ├─ schema.sql             可独立查阅的 SQLite 建表脚本
│  ├─ openapi.json           可离线查阅的接口定义
│  └─ data/                  运行后创建的数据库、签名密钥与素材（不纳入版本管理）
├─ frontend/
│  ├─ src/views/             登录、工作台、店铺、商品、导入和设置页面
│  ├─ src/components/        商品九个标签页及通用表单、图表组件
│  ├─ src/api.ts             请求封装、登录状态、提示与格式化
│  ├─ src/forms.ts           复用表单与提交逻辑
│  ├─ src/router.ts          页面路由与登录访问检查
│  └─ src/style.css          中文工作台样式与响应式布局
├─ scripts/                  Windows 安装、启动和验证脚本
├─ templates/                可直接填写的 CSV 模板
└─ docs/                     接口说明、验收映射与从零开发路线
```

普通请求：页面 → `api.ts` → FastAPI 路由 → 登录/角色依赖 → 输入校验 → 业务服务 → SQLAlchemy 事务 → SQLite。

素材任务：页面提交 → 方案归属校验 → 持久化任务与入队事件 → 后台原子领取并分配尝试租约 → 生成文件 → 再次检查取消/超时/租约 → 素材入库与成功事件。任务不依赖浏览器一直开着，页面有活动任务时每 2.5 秒刷新一次。

## 单独开发前后端

首次安装：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

终端一，在项目根目录执行：

```powershell
Set-Location .\backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
```

终端二，在项目根目录执行：

```powershell
Set-Location .\frontend
npm run dev
```

访问 <http://127.0.0.1:5173>。Vite 会把 `/api` 和 `/media` 代理到 8765；若变更后端端口，将 `frontend/.env.example` 复制为 `frontend/.env` 并修改 `VITE_API_TARGET`。

数据库独立初始化与演示数据：

```powershell
Set-Location .\backend
..\.venv\Scripts\python.exe scripts/init_db.py --demo --export-sql
```

`schema.sql` 由数据模型生成；账户密码哈希和演示资料通过初始化脚本创建，不写成明文 SQL 数据。表结构调整后应补迁移脚本，不建议删除已有数据库来升级。

## 连接真实模型

将 `backend/.env.example` 复制为 `backend/.env`，按自己的服务配置：

```dotenv
AI_MODE=compatible
AI_BASE_URL=https://your-provider.example/v1
AI_API_KEY=your-secret
AI_TEXT_MODEL=your-text-model
AI_IMAGE_MODEL=your-image-model
```

不要提交实际 `.env`。后端仅返回配置是否完整，网页不回传密钥。修改服务地址、模型或密钥后重启后端；网页中的模式与队列参数可持久化调整。

- 文本请求：`POST {AI_BASE_URL}/chat/completions`，使用 `messages` 和 `response_format={"type":"json_object"}`。服务必须支持该协议及 JSON 输出。无效输出返回 502，不保存不完整的报告。
- 图片请求：`POST {AI_BASE_URL}/images/generations`，包含 `model`、`prompt`、`size=1024x1024`、`n=1`、`response_format=b64_json`，返回 `data[0].b64_json`。
- 视频适配：设置 `VIDEO_API_URL` 和 `VIDEO_API_KEY`。后台以 Bearer 鉴权向完整适配地址 POST `{"prompt":"商品与脚本 JSON","format":"mp4","duration_sec":6}`，期望返回 `{"video_base64":"MP4 内容的 base64"}`。服务商若使用提交/轮询协议，应在自己的适配服务中完成转换，或替换 `services/media.py` 中的视频分支。

以上不同供应商不一定兼容。未配置服务或调用失败时任务会真实标记失败，不静默伪装成模型成功。

## 导入与指标口径

导入使用 UTF-8 CSV，可带 BOM。模板中的 `store_id`、`product_id` 必须指向已有记录。导入预览用保存点模拟实际写入，最后整体回滚；正式导入每行使用独立保存点，所以坏行不会影响其他有效行。CSV 行号包含表头，第一条数据为第 2 行。

SKU 库存导入仅新增；已有 SKU 编码返回行级错误。已有库存应使用库存调整接口，防止重复导入覆盖流水。正式导入前会再次校验；多人同时修改时，结果可能与较早的预览不同。

- CTR = 点击 / 曝光。
- 点击转化率 CVR = 成交 / 点击。
- 本项目 ROI = 收入 / 花费，不是净利润回报率；分母为 0 时记为 0。
- 数量必须满足曝光 ≥ 点击 ≥ 成交，金额不允许负数或非有限数。
- 复盘只聚合完整落在所选日期区间内的记录，不擅自分摊跨日记录。
- 工作台展示近 14 天汇总；趋势图仅使用单日记录，跨日记录只计入合计。
- 所有页面日期按上海时区呈现；数据库事件保存 UTC 时间。

## 后台执行与数据保留

默认 Web 进程内启动一个任务线程和一个竞品调度线程。素材队列每秒检查；竞品调度每 30 秒检查到期监控，每轮最多 5 个，单个监控间隔至少 60 分钟。页面手动执行到期监控最多处理 20 个。公开解析固定校验后的公网 IP，逐跳校验重定向，限制为 1 MB 静态 HTML，不访问本机或内网。

如需把任务和 Web 分开：设置 `WORKER_ENABLED=false` 后启动 Web，再在另一个终端运行：

```powershell
Set-Location .\backend
..\.venv\Scripts\python.exe scripts/run_worker.py
```

SQLite 适合当前本地、小团队版本；默认使用单个 Web 进程。数据库、签名密钥及生成文件都在 `backend/data/`，备份时一起备份。服务重启后待处理任务仍在，遗留运行中任务超过超时阈值后标记超时，用户可在次数限制内重试。
