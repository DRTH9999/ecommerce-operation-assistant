# 本地验收记录

验证日期：2026-10-21，上海时区。环境：Windows、Python 3.13.9、Node.js 24.16.0、SQLite。本次使用本地演示模式，没有调用真实付费模型或真实平台账号。

## 自动检查

运行 `scripts/check.ps1`，后端 **18 项测试通过**，前端 `vue-tsc` 类型检查与 Vite 正式构建通过。

- 完整闭环：商品 → 诊断 → 三个主图方向 → 图片任务 → 素材审核 → 投放建议确认 → 实验状态流转 → 经营数据 → 复盘 → 下一轮诊断。
- 视频输出：异步任务生成 MP4，校验 MIME、文件头、任务成功状态及演示来源标识。
- 库存：禁止扣成负数、禁止低于锁定量，库存调整与流水保持一致。
- 导入：预览后数据库不变；正式导入允许部分成功；同批重复 SKU 与错误 CSV 编码能准确反馈。
- 权限：查看人员能读不能写，不能管理用户、确认投放建议或更新实验；停用用户后旧令牌失效。
- 数据归属：跨商品方案编辑和跨商品经营数据引用被拒绝。
- 任务：失败、重试、取消、超时及取消后迟到输出不入库。
- 平台账号：不接受 token 等额外字段，授权占位 state 不能重复使用。
- 公开解析：拒绝回环地址；错误保留到任务日志。
- 竞品监控：记录公开元信息，未到期不重复执行，解析失败不会覆盖人工竞品价格。
- 生成输出：保留主图 `copy` 序列化字段；真实接口返回残缺结构时拒绝保存；预算字段拒绝非法值。
- 演示数据：重复初始化不重复建档，覆盖商品运营所需全部模块。

测试框架产生一条来自 Starlette TestClient 的 HTTPX 兼容性弃用提示；业务测试与构建结果均通过，生产页面运行未出现相应错误。

## 浏览器实际操作

使用本地 Microsoft Edge 与 Playwright CLI 完成：

1. 管理员登录，工作台读取三家店铺、六件商品和合成经营趋势。
2. 打开随行保温杯主图方案，修改核心文案并保存，页面刷新后仍保留修改。
3. 提交图片任务，在任务页观察到入队、运行、成功和素材入库结果。
4. 上传含一条有效记录和一条错误记录的经营 CSV，预览提示可导入 1 行、错误 1 行，指出第 3 行错误。
5. 确认导入后，成功 1 行、失败 1 行；有效记录可在复盘页查看。
6. 生成新复盘，报告按 15 条记录汇总，包括刚刚导入的有效行。
7. 独立查看人员登录，能查看投放建议及实验，页面不显示生成、编辑、确认或实验更新按钮。

页面加载检查覆盖 14 个页面/标签内容：店铺列表、店铺详情、商品列表、商品九个标签、导入中心、设置。未发现 JavaScript 页面错误。

390 × 844 视口检查覆盖工作台、商品列表、商品档案、投放、导入、设置六页，页面宽度均为 390，无页面级横向溢出；宽表格可在表格区域内横向滚动。
