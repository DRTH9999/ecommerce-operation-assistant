# 从零开发：按真实代码理解这个项目

这份路线针对当前已经写出的本地代码，不把需求文档中的外部平台能力当成已经接入的服务。

## 1. 整体架构

用户看到的是 Vue 页面；页面调用 FastAPI 的业务接口；接口验证身份、角色和输入；服务层执行库存、任务、导入与报告规则；SQLAlchemy 将数据持久化到 SQLite。图片和视频通过持久化队列交给后台线程执行，普通页面请求只负责创建任务。

先掌握三条数据关系：

1. 店铺 → 商品 → SKU → 库存 → 库存流水。
2. 商品 → 诊断 → 主图/视频方案 → 生成任务 → 素材 → 审核。
3. 商品 → 投放建议 → 人工确认 → 实验 → 经营记录 → 复盘 → 下一轮诊断。

## 2. 目录职责与阅读顺序

| 顺序 | 文件 | 先回答什么问题 |
| --- | --- | --- |
| 1 | `backend/app/config.py` | 服务名称、数据库、模型和队列参数从哪里来？ |
| 2 | `backend/app/models.py` | 每种业务对象保存哪些字段，哪些外键和约束不能违反？ |
| 3 | `backend/app/db.py` | 一次请求如何取得连接、提交事务或回滚？ |
| 4 | `backend/app/schemas.py` | 外部输入和模型输出允许什么形状？ |
| 5 | `backend/app/security.py` | 怎样识别用户，为什么查看角色无法写入？ |
| 6 | `backend/app/routers/auth.py` | 登录如何校验密码并签发访问令牌？ |
| 7 | `backend/app/services/catalog.py` | 商品、SKU、库存、流水及经营指标如何保持一致？ |
| 8 | `backend/app/routers/catalog.py` | URL 和输入参数怎样落到商品业务函数？ |
| 9 | `backend/app/services/ai.py` | 规则演示与真实文本服务怎样使用同一输出结构？ |
| 10 | `backend/app/services/jobs.py` | 为什么任务要先入库，取消/重试/超时怎样避免迟到结果？ |
| 11 | `backend/app/services/media.py` | 生成图片/视频文件与把素材入库分别发生在哪里？ |
| 12 | `backend/app/services/imports.py` | 怎样先预览不落库，再按行部分成功？ |
| 13 | `backend/app/routers/operations.py` | 商品运营九个标签对应哪些业务接口？ |
| 14 | `backend/app/main.py` | 如何把路由、数据库、执行器和前端托管组装成应用？ |
| 15 | `frontend/src/api.ts`、`router.ts` | 前端怎样保持登录状态、发送请求和限制页面访问？ |
| 16 | `frontend/src/views/ProductDetail.vue` | 商品数据怎样分发给九个标签组件？ |

`models.py` 中的 `Table`、`Column`、`ForeignKey` 是 SQLAlchemy 提供的 API；本项目的 `table()`、`ref()`、`num()` 是为了复用字段声明而写的辅助函数。`schemas.py` 中的 `BaseModel`、`Field`、`field_validator` 来自 Pydantic；`create_product()`、`enqueue()`、`save_performance()` 等 `def` 才是自己的业务函数。

## 3. 跟一条真实请求：调整 SKU 库存

1. `ProductBaseTab.vue` 的“调整库存”打开 `FormModal.vue`。
2. 表单收集 `change_qty`、`locked_qty`、`warning_threshold`、`location_text`、`reason_text`。
3. `forms.ts` 的提交方法通过 `api.ts` 发出带 Bearer 令牌的 POST。
4. `routers/catalog.py` 的库存接口依赖 `writer`，查看人员在此被拒绝。
5. `InventoryAdjust` 校验整型范围和必填原因。
6. `services/catalog.py::adjust_inventory()` 验证 SKU 属于当前商品，再读取原库存。
7. 计算新库存，拒绝负数或低于锁定量；使用原数量作为更新条件防止覆盖其他调整。
8. 同一事务写库存表与流水表；任一步失败都会回滚。
9. 页面刷新商品详情，显示最新可用库存和流水。

这条请求的形状是：一个商品编号、一个 SKU 编号、一个 JSON 对象。结果是单条库存对象；详情接口返回的是商品对象，其中 `skus`、`inventory_movements` 等字段是对象数组。

## 4. 跟一条异步流程：生成图片

1. 主图组件提交方案编号。
2. `enqueue()` 校验方案归属、类型、归档状态和已有活动任务，写入 `pending` 任务与 `queued` 事件。
3. 后台 `JobWorker.claim()` 用条件更新领取一条任务，并增加尝试次数、生成本次租约标识。
4. 数据库事务结束后，`generate_media()` 才调用服务或生成演示文件，避免网络调用期间持有写事务。
5. 文件生成后重新检查任务状态和租约；如果被取消或旧尝试已经超时，删除本次文件，不创建素材记录。
6. 有效结果同时更新任务为成功、创建素材并写成功事件。
7. 前端轮询看到任务完成，在素材库展示待审核素材。

生成文件、登记素材、审核素材是三个不同步骤。演示规则产出的 SVG 不代表已调用图片模型；6 秒 MP4 是动态分镜示意，不代表已经接入真实视频模型。

## 5. 如果亲手重写，从哪一步开始

1. 先写最小 `/api/health`，确认服务能启动。
2. 写配置、数据库和 `users/stores/products`，完成登录与店铺/商品增查改。
3. 加 SKU、库存和流水；先把一致性与权限验证跑通。
4. 加竞品、诊断和创意方案，先使用结构化演示规则。
5. 设计任务状态机与事件，再加入文件生成、失败、取消和超时。
6. 加素材人工审核、推广链接与点击统计。
7. 加投放建议人工确认与实验状态机。
8. 加经营数据、指标计算和复盘，闭合回到诊断的路径。
9. 做导入保存点、预览与错误行反馈，再准备演示数据。
10. 做页面与接口联调；用真实点击检查保存后刷新，而不仅验证页面能显示。
11. 接入真实供应商时只替换服务适配层，继续保留结构校验、权限、任务记录和人工确认。

## 6. 当前实现进度与下一阶段

本地业务闭环、数据库、接口、前端、演示生成、公开元信息解析、任务状态机和 CSV 导入已实现。真实平台 OAuth、平台商品同步、供应商视频异步轮询等需要具体平台协议与授权后继续接入。

目前默认小团队共享一个工作区，按角色控制操作，没有做租户间数据隔离；如果将来服务多个客户，须增加租户/店铺成员关系和查询级隔离。扩展到生产部署时还应根据部署要求补数据库迁移、HTTPS、备份策略与多实例队列。这些均不应被误认为本次已完成的本地能力。
