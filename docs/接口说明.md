# 接口说明

接口前缀为 `/api/v1`。完整字段、输入约束和响应结构可在启动后的 `/docs` 页面查看，也可离线阅读 `backend/openapi.json`。

## 鉴权与权限

登录请求：

```http
POST /api/v1/auth/login
Content-Type: application/json

{"username":"admin","password":"Admin@123456"}
```

成功返回 `access_token`、`token_type`、有效期秒数和不含密码哈希的用户信息。业务接口发送：

```http
Authorization: Bearer <access_token>
```

例外是公开健康检查 `/api/health`、登录接口、素材文件与推广跳转。推广跳转按设计允许未登录访问，以记录外部访客点击。新增、更新、生成、导入、确认、取消、重试和手动调度均在后端验证角色。

| 操作 | 管理员 | 运营人员 | 查看人员 |
| --- | --- | --- | --- |
| 查询工作台、店铺、商品及运营资料 | 允许 | 允许 | 允许 |
| 管理店铺与平台账号占位 | 允许 | 拒绝 | 拒绝 |
| 编辑商品、SKU、库存、竞品、诊断、方案、素材、链接和经营数据 | 允许 | 允许 | 拒绝 |
| 确认/驳回投放建议 | 独立权限检查 | 独立权限检查 | 拒绝 |
| 更新实验计划/状态 | 独立权限检查 | 独立权限检查 | 拒绝 |
| 用户管理、系统配置、演示初始化和手动超时扫描 | 允许 | 拒绝 | 拒绝 |

密码使用带随机盐的 scrypt 哈希；令牌使用持久化签名密钥与用户令牌版本。退出、改密码、改角色或停用后，旧令牌失效。当前版本是同一团队共享工作区，不提供租户隔离。

## 创建商品、SKU 和库存流水

创建店铺：

```json
{"store_name":"我的店铺","platform":"taobao","owner_name":"运营负责人"}
```

发送到 `POST /stores`，取得 `id` 后创建商品：

```json
{
  "store_id": 1,
  "name": "轻量随行保温杯",
  "platform": "taobao",
  "category": "家居 / 水具",
  "price": 129,
  "cost": 48,
  "target_audience": "通勤人群",
  "selling_points": "轻量杯身、防漏结构",
  "product_url": "https://example.com/item",
  "images_json": [],
  "status": "draft"
}
```

发送到 `POST /products`。商品平台必须与店铺一致；其他平台使用 `/products/{product_id}/platform-mappings` 关联。

创建 SKU：

```json
{"sku_code":"CUP-GREEN","sku_name":"森林绿 / 350ml","price":129,"cost":48,"stock_qty":100,"warning_threshold":20,"location_text":"A-01"}
```

发送到 `POST /products/{product_id}/skus`，初始非零库存自动生成流水。同一商品下 SKU 编码唯一。库存调整：

```json
{"change_qty":-5,"reason_text":"日常出库","locked_qty":0,"warning_threshold":20}
```

发送到 `POST /products/{product_id}/skus/{sku_id}/inventory-adjustments`。变动后不能小于 0 或锁定量；条件更新失败返回 409，刷新后重试。阈值或库位调整可以使用 `change_qty=0`，同样留流水。

## 结构化生成与编辑

- `POST /products/{product_id}/diagnoses/generate`：生成七个结构化诊断字段。
- `POST /products/{product_id}/creative-plans/main-images/generate`：已有诊断时生成至少三个主图方向，每个方案保存标题、`layout`、`copy`、`selling_point`、理由。
- `POST /products/{product_id}/creative-plans/video-scripts/generate`：保存标题、`hook`、`shots` 数组、`voiceover`、`cta`、理由。
- 各对象支持 PATCH。诊断、投放建议和复盘支持单字段修改；方案内容更新时，`content_json` 须包含该类型完整结构。
- 投放建议包含摘要、目标、人群数组、预算对象、素材测试数组、出价对象、风险数组、下一步数组。预算对象包含非负 `daily_budget`、`total_budget`、正整数 `days` 与 `note`。
- 复盘包含 `summary_text`、`insights_json`、`problem_judgment` 和 `next_actions_json`。

模型返回不符合结构时返回 502，不保存残缺内容。演示结果标记 `demo_rules`，真实文本接口结果标记 `compatible_model`。

## 素材任务与审核

提交方案素材任务：

```http
POST /api/v1/products/{product_id}/creative-plans/{creative_plan_id}/images/generate
POST /api/v1/products/{product_id}/creative-plans/{creative_plan_id}/videos/generate
```

返回 202 和任务对象，表示入队，不能据此判断生成成功。查询商品详情或 `GET /products/{product_id}/generation-jobs` 获取任务与事件。

状态为 `pending/running/succeeded/failed/cancelled/timeout`。失败或超时且未达到最大尝试次数时，可以 POST `.../generation-jobs/{job_id}/retry`；待处理或运行中可以 POST `.../cancel`。

`PATCH /products/{product_id}/assets/{asset_id}` 接受：

```json
{"review_status":"approved","version_no":2,"usage_scene":"商品主图","score":4.5,"tags_json":["主图","卖点"],"remark":"已核实文案与参数"}
```

也兼容开发文档的方案级 `/creative-plans/{creative_plan_id}/assets` 路径，额外指定 `asset_id`。素材必须同时属于当前商品和当前方案。

## 投放确认与实验

生成投放建议前至少需要一份审核通过的素材。确认请求：

```http
PATCH /api/v1/products/{product_id}/ad-recommendations/{recommendation_id}/confirmation

{"confirm_status":"confirmed","confirm_remark":"已核对预算与库存"}
```

也可使用 `rejected`。只允许处理 `pending` 建议，记录操作人和时间。已处理建议不能修改正文或重复处理，应生成下一版。

创建实验时指定已确认建议：

```json
{"recommendation_id":1,"related_asset_id":1,"related_link_id":1}
```

发送到 `/products/{product_id}/ad-experiments/generate`。素材必须审核通过；引用其他商品的资料返回 404。状态允许 `draft → confirmed → running → finished`，前三种状态可转 `cancelled`。确认后不再修改预算和实验条件。

这些动作只保存计划与处理记录，不调用广告平台。

## 推广链接与点击

`POST /products/{product_id}/promotion-links` 接受名称、HTTP/HTTPS 目标地址、`utm_json` 和场景。返回随机 `tracking_code`。

外部访问 `/api/v1/r/{tracking_code}` 时写点击明细并原子增加计数，随后 302 跳转到添加追踪参数的目标地址。只统计经过该地址的点击，不推断平台总点击与成交归因。

## 经营数据与复盘

```json
{
  "period_start": "2026-10-21",
  "period_end": "2026-10-21",
  "impressions": 8000,
  "clicks": 240,
  "conversions": 8,
  "spend": 120,
  "revenue": 1032,
  "notes": "统一归因口径的日汇总"
}
```

发送到 `POST /products/{product_id}/performance-records`。可选关联方案、素材、链接和实验，但所有引用必须属于当前商品。CTR、转化率与 ROI 由服务端计算，客户端不能直接提交覆盖。

复盘生成请求只提供日期：

```json
{"period_start":"2026-10-08","period_end":"2026-10-21"}
```

发送到 `/products/{product_id}/review-reports/generate`。没有完整落入所选区间的数据时返回 409。最近复盘会作为下一轮诊断的输入。

## CSV 模板与导入

`GET /workspace/templates/{kind}` 中 `kind` 支持 `products`、`sku-inventory`、`performance-records`、`platform-mappings`。这一个参数化路由覆盖开发文档中的具体模板下载地址。

JSON 导入先 POST `/workspace/imports/{kind}/preview`：

```json
{"rows":[{"store_id":1,"name":"示例商品","platform":"taobao","price":39.5}]}
```

也可 multipart 上传文件到 `/workspace/imports/{kind}/preview-file`，文件字段名为 `file`。预览没有正式写入。确认后将相同 `rows` 发到 `/workspace/imports/{kind}`。商品专属经营数据导入接口 `/products/{product_id}/performance-records/import` 也支持 `rows`；提交其他商品的编号会被拒绝。

返回 `total`、`success_count`、`error_count`、`successes`、`errors`、逐行预览 `rows`。错误记录包含实际 CSV 行号和中文原因，第一条数据的行号为 2。正式导入允许部分成功，并重新验证数据。

## 错误与状态码

| 状态码 | 含义 |
| --- | --- |
| 200 / 201 / 202 | 操作完成 / 已创建 / 任务已入队 |
| 401 | 登录缺失、过期、停用或令牌版本已变化 |
| 403 | 当前角色没有对应权限 |
| 404 | 记录不存在，或不属于当前商品/店铺 |
| 409 | 业务状态冲突、库存不足或重复数据 |
| 413 | 上传文件超过限制 |
| 422 | 字段校验错误、日期/漏斗规则不满足或链接不被允许 |
| 429 | 登录尝试过于频繁 |
| 502 | 真实模型服务调用失败或返回内容无效 |

普通业务错误返回 `{"detail":"中文原因"}`；字段校验错误返回 `detail` 数组，只含位置、类型与中文说明，不回显密码等原始输入。公开链接任务和竞品监控的解析失败保存到任务/快照中，调用接口可正常返回 200，须检查内部状态。
